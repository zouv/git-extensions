# 01 · 技术栈说明

> 面向使用者/维护者：本项目用了哪些技术、为什么这么选、各自负责什么。
> 代码在哪、怎么连，见 [`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

| 层 | 选型 | 负责什么 | 为什么 |
|---|---|---|---|
| 桌面壳 | Tauri 2 | 窗口、IPC、打包 | 比 Electron 省内存；Rust 后端便于做异步 git 操作 |
| 后端 | Rust + git2（libgit2） | 日志、分支、状态、diff 等读操作 | 库内调用省掉进程派生与输出解析，高频查询开销低 |
| 后端写操作 | git CLI 子进程 | stage / commit / branch / checkout / delete | libgit2 不执行 hooks；CLI 行为与用户命令行完全一致 |
| 前端 | React 19 + TypeScript 严格模式 | 界面与状态 | 组件化 + 类型与 Rust serde 对应，改字段双端可对照 |
| 构建 | Vite + pnpm；cargo | 前端热更新与产物；后端编译 | 常规组合，无特殊定制 |
| 渲染 | 自研虚拟化列表 + Canvas | 万级提交列表、分支图、大 diff、blame | DOM 只挂可见行；图只画可见区域，避免大列表卡死 |
| 语法高亮 | highlight.js + Web Worker | diff 代码 token 着色 | 高亮移出 UI 线程；旧请求结果丢弃，大文件自动跳过 |

关键设计：日志经 `log-batch` 事件分批推送，前后端各有一个代际号作废旧请求；后端不保存仓库全局状态，每个命令按路径重新打开仓库。
