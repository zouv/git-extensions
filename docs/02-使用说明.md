# 02 · 使用说明（部署 / 维护 / 调试）

> 面向使用者/维护者的操作手册。技术选型见 [`01-技术栈说明.md`](01-技术栈说明.md)；代码在哪、怎么连见 [`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 部署 / 启动

1. 装齐前置：Rust（rustup）、Node.js 22+、pnpm、git；Windows 需系统 WebView2 运行时。
2. 运行 `setup.bat`（或 `pnpm install`）安装依赖。
3. 开发运行：`dev.bat`（首次会编译 Rust 依赖，耗时较长）；发布打包：`package.bat`，产物在 `src-tauri/target/release/bundle/`。
4. 使用：点「打开仓库」输入本地仓库路径；下次启动自动重开上次仓库。底部页签：提交（详情）、差异（选中提交的 patch）、变更（暂存与提交）。工具栏：分支 / 标签 / Stash / 子模块弹窗，Fetch / Pull / Push，过滤框。提交行右键：Cherry-pick / Revert / Rebase。写操作后自动全量刷新；工作区变更另有 5 秒轮询自动刷新。
5. 左侧「引用」面板按本地分支 / 远程分支 / 标签分组：单击过滤提交图，双击非当前本地分支可切换。diff 文件列表右键可打开 Blame 或文件历史。
6. 快捷键：Ctrl+O 打开仓库，F5 刷新，Ctrl/Cmd+F 聚焦过滤，Ctrl/Cmd+B 切换引用面板，Ctrl/Cmd+1/2/3 切换底部页签，Esc 关闭弹窗。提交列表支持方向键、Home/End、PageUp/PageDown 和 Enter；Ctrl/Cmd+Shift+C 复制完整 SHA。提交信息框内 Ctrl/Cmd+Enter 提交。
7. 工具栏「设置」（Ctrl/Cmd+,）可配置自动刷新、3–60 秒轮询间隔、语法高亮、左侧面板和 1–20 万条日志上限，设置保存在本机。弹窗内可查看分支、Stash、标签、子模块及 Fetch / Pull / Push 的完整快捷键。

## 维护

- 版本号在两处保持同步：`package.json` 与 `src-tauri/Cargo.toml`（发版时一起改，并更新 `tauri.conf.json`）。
- 上次仓库路径存在 WebView 的 localStorage（键 `git-extensions.lastRepo`），行为设置存在 `git-extensions.settings`；清除应用数据即可重置。
- 无其它本地数据文件；应用本身不写仓库以外的状态。

## 调试

- 界面异常：开发模式下用 WebView 开发者工具看控制台；状态栏会显示后端返回的 git 错误原文。
- 后端问题：`test.bat` 跑完整测试（前端检查 + Rust 单测 / 集成测试）；集成测试在临时目录建真实仓库，覆盖读写全流程、stash、rebase、tag、submodule、blame / 文件历史与本地裸远程的 push / fetch / pull。
- 写操作失败多为 git 自身报错（hooks 拒绝、分支未合并、rebase 冲突等），按 stderr 提示处理；rebase / cherry-pick 冲突需到命令行解决后刷新。
- 前端类型与后端字段对不上：对照 `src/types.ts` 与各 Rust 结构的 serde 定义（统一 camelCase）。
- 文档体检：`sh check-docs.sh`。
