# 02 · 使用说明（部署 / 维护 / 调试）

> 面向使用者/维护者的操作手册。技术选型见 [`01-技术栈说明.md`](01-技术栈说明.md)；代码在哪、怎么连见 [`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 部署 / 启动

1. 装齐前置：Rust（rustup）、Node.js 22+、pnpm、git；Windows 需系统 WebView2 运行时。
2. 运行 `setup.bat`（或 `pnpm install`）安装依赖。
3. 开发运行：`dev.bat`（首次会编译 Rust 依赖，耗时较长）；发布打包：`package.bat`，产物发布到 `dist/release/`：NSIS / MSI 安装包、`unpack/` 免安装便携目录（双击其中 exe 运行，需 WebView2）、`Git.Extensions_<版本>_x64-unpack.zip` 与 `SHA256SUMS.txt`。前端构建产物在 `.runtime/dist/`；构建前会记录已有安装包指纹，只导出本次新生成的产物。若便携版正从 `dist/release/unpack` 运行，脚本会先列出占用进程并询问是否强制关闭（非交互环境可设置 `GIT_EXTENSIONS_FORCE_CLOSE=1`）；拒绝或关闭失败时会明确说明原因后退出。
4. 点「打开仓库」输入本地仓库路径。仓库显示为顶部页签，可同时打开多个；重复打开只会激活已有页签。中键或右键可关闭页签，忙碌中的仓库不能关闭。

## 界面与工作流

### 历史与变更

- 左侧「本地变更」显示未暂存、已暂存文件和提交编辑器；选择「全部提交」、分支或标签时，右侧显示对应的提交历史与详情 / 差异检查器。
- 导航、主内容与检查器之间的分隔条支持拖拽、方向键调整和双击复位；检查器可移到右侧 / 底部、最大化或关闭。布局按仓库保存，状态栏可一键恢复默认布局。
- 左侧本地分支 / 远程分支 / 标签 / Submodules / Worktrees 分组支持折叠；单击引用过滤历史，双击非当前本地分支可切换。子模块行打开子模块管理，Worktrees 行右键可复制路径或在文件管理器中显示。底部固定 Stash 与子模块入口。提交行右键提供复制、对比、建分支 / 标签、Cherry-pick、Revert 和 Rebase。
- 变更区可过滤文件、批量或选中暂存 / 取消暂存，提交标题与正文分开。文件右键可打开、在文件管理器中显示、复制路径、查看历史 / Blame、丢弃未暂存变更或删除未跟踪文件。丢弃与删除均需应用内确认。
- 差异视图支持 Inline / Split 两种模式；工具栏的上一处 / 下一处差异按钮对应 Alt+↑ / Alt+↓，并可折叠未修改片段。本地变更的单文件预览不再重复显示文件名与文件列表；提交差异的文件切换通过左侧文件列表完成，列表 / 目录树切换位于文件列表顶部；文件地址栏与功能栏位于右侧差异面板顶部。

### 对比

工具栏「对比」或 Ctrl/Cmd+3 打开临时对比视图。两端可输入提交 SHA、分支或标签，支持交换并复用统一 diff；也可在提交 / 分支右键菜单直接进入。对比读取两个提交的实际 tree，不是 `A..B` 提交范围。

### 冲突解决中心

Merge、Cherry-pick、Revert 或 Rebase 进入冲突状态后，可从变更区打开冲突中心：

1. 选择冲突文件，对照「当前 / 传入」两侧，在合并结果中编辑；也可采用其中一侧。
2. Ctrl/Cmd+S 或「保存并标记为已解决」会写入文件并暂存，不会自动继续操作。
3. 全部文件解决且当前编辑已保存后，点「继续」。若下一步仍有冲突，中心会保留并显示新进度。
4. 「中止」会放弃本次操作及解决进度，必须单独确认。切换文件或离开时有未保存编辑也会提示。

### 交互式 Rebase

在提交右键选择「交互式 Rebase」，可对该提交及其后的线性提交重排，或设置 pick / reword / squash / fixup / drop。列表最旧在上、最新在下；拖动和 Alt+方向键只编辑计划，不会立即修改仓库。点「开始 Rebase」并确认后才执行。

首版只支持非根提交开始的线性范围；包含 merge commit、工作区不干净或计划不完整时后端会拒绝。drop 和重写历史需要危险确认；执行中遇到冲突会接入冲突解决中心。

## 快捷键

- 全局：Ctrl/Cmd+O 打开仓库，Ctrl/Cmd+W 关闭当前仓库，Ctrl+Tab 切换仓库，Ctrl/Cmd+, 打开设置。
- 工作区：Ctrl/Cmd+1 历史，Ctrl/Cmd+2 变更，Ctrl/Cmd+3 对比，Ctrl/Cmd+B 切换导航，F5 刷新，F6 / Shift+F6 在区域间移动焦点。
- 历史：Ctrl/Cmd+F 聚焦过滤；方向键、Home/End、PageUp/PageDown 导航，Enter 查看 diff，Ctrl/Cmd+Shift+C 复制完整 SHA。右键菜单也可用 Shift+F10 打开。
- 操作：分支、Stash、标签、子模块和 Fetch / Pull / Push 的 Ctrl/Cmd+Shift 快捷键见设置弹窗；提交编辑器内 Ctrl/Cmd+Enter 提交。
- Esc 依次还原最大化检查器、关闭临时任务或弹窗。弹窗支持焦点循环并在关闭后恢复原焦点。

## 设置与本地数据

工具栏「设置」可配置自动刷新、3–60 秒轮询间隔、语法高亮、新仓库默认导航和 1–20 万条日志上限。后台仓库暂停轮询，切回时恢复；刷新不会主动清空提交草稿。

本地数据仅在 WebView localStorage：行为设置 `git-extensions.settings`、打开页签 `git-extensions.openRepos.v1`（有序仓库路径；空数组表示已关闭全部页签）、上次仓库 `git-extensions.lastRepo`、最近仓库 `git-extensions.recentRepos.v2`、按仓库布局前缀 `git-extensions.layout.v2:`、仓库页签分组 `git-extensions.repoGroups.v1`（含分组与颜色、仓库分配、多选活动组与页签别名）。清除应用数据即可重置；应用不把仓库内容或路径发送到外部服务。

## 顶部栏与仓库页签分组

- 顶部栏自绘（无系统标题框）：最左应用图标（左键菜单：打开仓库 / 设置 / 关于 / 关闭窗口），其右为一体化的仓库页签分组入口与已 Pin 分组图标，再右是仓库页签和最小化 / 最大化 / 关闭按钮。页签栏末尾的「+」紧贴最后一个页签，页签过多时仍保持可见，可用滚轮横向滚动。拖动标题栏或页签栏空白处移动窗口，双击空白处切换最大化 / 还原，右键空白处打开应用菜单，边缘可缩放。
- 页签悬停时右侧显示关闭 X（不改变页签宽度），点击 X 或中键点击页签只关闭目标页签。右键页签可关闭 / 关闭其它 / 在右侧打开仓库… / 设置显示名 / 复制路径 / 在文件管理器中显示。拖动页签超过 6px 才进入排序并显示插入线；按 Esc、拖出页签栏或在栏外释放会取消排序，拖到页签栏边缘会自动滚动。键盘可用左右方向键与 Home/End 切换页签，Shift+F10 或菜单键打开页签菜单。
- 分组管理的是**打开的仓库页签**（不是 Git 标签）：通过分组入口按钮或「管理分组」新建 / 重命名 / 删除 / Pin 分组，未分组页签归入 Default。
- 分组支持多选：标题栏分组入口菜单可勾选多个组，页签栏只显示所选组的仓库页签并集。每个组菜单项右侧的 Pin 按钮可快速切换常驻状态，不改变组筛选；被 Pin 的分组图标常驻顶部栏，左键切换该组是否显示，右键打开分组菜单，图标可拖拽排序。
- 「管理分组」界面可直接更换每个仓库页签的分组、点击当前色块弹出预设色板选择组颜色、编辑页签显示名（别名），并明确显示「Pin / 已 Pin」状态；页签右键「设置页签显示名…」同样可编辑别名。组颜色同步用于头像、菜单和页签顶部色条，便于多组并集显示时区分归属。别名只影响页签显示，仓库路径与 Git 操作不变，留空恢复仓库名。
- 关闭应用后重新打开，会按原顺序恢复上次打开的仓库页签和活动页签；已删除 / 移动的仓库会跳过并在通知中提示一次。恢复时只加载活动页签，其余页签首次点击后才读取提交日志与状态。
- 关闭页签只关闭界面会话，不删除仓库；删除分组只把组内页签移回 Default，不会关闭或删除仓库。当前活动仓库被隐藏时会自动切到当前组第一个可见页签；组内没有打开的仓库时显示提示。新打开的仓库页签归入当前选中的组（Default 可见时归入 Default），保证打开后立即可见。

## 维护 / 调试

- 版本号在三处保持同步：`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`。
- 界面异常：开发模式下用 WebView 开发者工具看控制台；状态栏显示简要结果，通知中心可查看和复制 Git 错误详情。
- 后端问题：`test.bat` 跑完整测试（前端检查 + Rust 单测 / 集成测试）。临时真实仓库测试覆盖基础读写、对比、staged 保留、未跟踪删除安全、冲突继续 / 中止与真实交互式 Rebase。
- 写操作失败会保留 Git stderr；若仓库真实进入冲突状态，直接在界面继续处理，不必转到命令行。
- 前端类型与后端字段对不上：对照 `src/types.ts` 与各 Rust 结构的 serde 定义（统一 camelCase）。
- 大仓库性能测量：`cd src-tauri && cargo run --release --example bench -- <仓库路径> 3`。
- 文档体检：`sh check-docs.sh`。
