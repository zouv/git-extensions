# 04 · UI 与交互重构设计方案

> **状态：待用户评审，尚未实施。** 本文是布局、交互与前端模块重构的实施依据；确认后再拆任务修改代码。
>
> 已确认方向：**双工作区、顶部仓库页签、专业 IDE 深色、首轮包含新 Git 工作流**。首轮新增范围为冲突解决中心、提交 / 分支对比、工作区文件操作和交互式 Rebase。

## 1. 设计目标与边界

### 1.1 目标

1. **交互便捷**：常用操作一至两步可达；鼠标、右键和键盘路径一致；切换仓库或面板不丢失工作上下文。
2. **布局专业**：以提交图、变更和 diff 为视觉中心；面板可调整、可折叠、可恢复，窗口变窄时仍可使用。
3. **反馈可信**：加载、写入、冲突、失败和后台操作都有明确状态，不用假进度，不只把错误塞进状态栏。
4. **模块可迭代**：工作区、面板、菜单、弹窗和命令解耦；新增 Git 功能不必继续堆进 `App.tsx` 或复制交互组件。
5. **保持性能与安全**：保留虚拟化提交图 / diff、日志代际取消、写操作走 CLI、后端显式传仓库路径等现有约束。

### 1.2 首版不做

- 不做任意面板拖拽停靠、自由浮动窗口或用户自定义布局脚本；提供受控的尺寸、位置和显隐调整。
- 不同步交付浅色主题，但颜色、间距、字号全部通过设计令牌定义，避免二次重构。
- 不做并排双栏 diff、合并算法编辑器、云端同步、外部头像服务或插件运行平台。
- 交互式 Rebase 首版只处理**线性提交范围**；包含 merge commit 的范围先阻止并解释，不静默改变历史拓扑。
- 不为了界面引入重型组件库。优先使用本地 SVG 图标和轻量自有组件；新增依赖需单独确认。

## 2. 现状问题与重构策略

| 现状 | 主要问题 | 重构策略 |
|---|---|---|
| 单仓库、单排工具栏 | 仓库上下文弱，按钮随宽度挤压，远程与管理操作混杂 | 仓库页签 + 分组命令栏；工作区相关命令随上下文出现 |
| 左侧引用树 + 上方提交图 + 固定底部页签 | 分栏不能拖，diff 与提交信息争用底部空间 | 历史 / 变更双工作区；详情支持右侧 / 底部，所有主分隔条可调 |
| 提交图和 diff 各自实现菜单 | 菜单位置、关闭行为、快捷键和危险操作样式不统一 | 统一 `ContextMenu`、`Dialog` 和命令注册，按上下文生成菜单 |
| 操作结果主要进入状态栏 | 成功不突出，失败缺少详情，长操作无法追踪 | 本地忙碌态 + 状态栏 + 通知中心三级反馈 |
| `App.tsx` 持有全部仓库与弹窗状态 | 多仓库会继续放大状态耦合，功能难以独立交付 | AppShell 与 RepoSession 分层，功能按工作区拆分 |
| 写操作失败只显示 Git stderr | 冲突是“可继续处理的状态”，却被当成终点 | 识别 merge / rebase / cherry-pick 状态，进入冲突解决中心 |

## 3. 信息架构与默认布局

### 3.1 应用骨架

```text
┌────────────────────────────── 系统标题栏 ──────────────────────────────┐
│ [project-a ●] [project-b ⚠2] [project-c]                         [+] │ 仓库页签
├───────────────────────────────────────────────────────────────────────┤
│ [☰] [刷新] │ main ▾  [Fetch] [Pull] [Push] │ 工作区命令 …  [搜索] [⚙] │ 命令栏
├────────────┬───────────────────────────────┬──────────────────────────┤
│ 历史 | 变更 │                               │                          │
│            │                               │                          │
│ 仓库导航    │          主工作区              │       详情 / diff         │
│ 分支        │     提交图或变更文件列表        │       检查器              │
│ 远程        │                               │                          │
│ 标签        │                               │                          │
│ Stash      │                               │                          │
│ 子模块      │                               │                          │
│            │                               │                          │
├────────────┴───────────────────────────────┴──────────────────────────┤
│ ● main ↑1 ↓2 │ 操作状态 / 最后消息              17,783 条 │ 通知 │ 布局 │ 状态栏
└───────────────────────────────────────────────────────────────────────┘
```

- **只有“历史”和“变更”两个常驻工作区。** 对比、冲突解决、交互式 Rebase 是由任务进入的临时视图，不继续增加顶层导航。
- **顶部栏自绘**：应用图标（左键菜单）+ 分组入口 + 已 Pin 分组图标 + 仓库页签 + 窗口控制合并为一栏，替代系统标题框（`decorations: false`）。窗口拖动、双击最大化、边缘缩放由 Tauri 原生处理；关闭窗口前汇总未保存草稿 / 进行中操作确认。
- 详情检查器默认在右侧，可切到底部；用户主动选择的位置不被窗口尺寸变化覆盖。
- 左侧导航始终属于当前仓库，单击引用过滤历史，双击本地分支仍表示切换，但右键提供完整替代路径。
- 所有区域使用 1px 分隔线，不用层层卡片和大幅留白制造“现代感”。

### 3.2 推荐尺寸

以 1440 × 900、100% DPI 为设计基准：

| 区域 | 默认 / 范围 | 说明 |
|---|---|---|
| 仓库页签栏 | 高 36px | 页签宽 160–240px，超出后横向滚动，不压缩成不可读小条 |
| 命令栏 | 高 44px | 图标按钮 28×28px；搜索框宽 240–360px |
| 左侧导航 | 默认 224px，160–360px | 可折叠；折叠后保留窄图标栏不是首版必需项 |
| 右侧检查器 | 默认 400px，320–720px | 可切底部、折叠或临时最大化 |
| 底部检查器 | 默认高度 280px，160–60% 窗口高 | 从右侧切到底部时保留各自尺寸 |
| 提交图 | 最小宽 420px | 图区域可横向收缩，提交信息优先于作者 / 日期列 |
| 分隔条 | 视觉 1px，命中区 8px | 拖拽时不改变总布局尺寸 |
| 状态栏 | 高 24px | 长消息省略，悬停查看完整内容，点击打开通知详情 |

窗口最小尺寸保持约 900 × 600；桌面端不做移动版布局。

### 3.3 分栏与布局规则

- 所有主分隔条支持鼠标 / 触控笔拖拽；获得焦点后方向键每次调整 16px，Shift+方向键调整 48px。
- 双击分隔条恢复该区域默认值；拖过折叠阈值后显示折叠预览，松手才折叠，避免误触。
- 面板标题栏提供折叠、最大化、关闭按钮；Esc 优先退出“临时最大化”，再关闭菜单 / 弹窗。
- 详情位置提供「右侧 / 底部」切换；diff 文件列表和变更的暂存区高度也可调。
- 提供三个预设：**默认**、**宽 Diff**（导航折叠、检查器加宽）、**专注历史**（检查器折叠）。另有「重置当前仓库布局」。
- 尺寸和位置按仓库保存，新仓库继承全局默认；数据写入带版本号的本地 UI 配置，非法数值回退默认。
- 首版不支持把任意面板拖到任意位置，以可预测的布局和可测试的快捷键优先。

### 3.4 窗口宽度适配

- **≥1280px**：默认三栏，详情在右侧。
- **960–1279px**：自动布局默认把详情放底部，导航可保留；用户已手动选择的布局不强制改变。
- **<960px**：命令栏低优先级操作进入「更多」，作者 / 日期列先收缩或隐藏，文件路径保留省略提示。
- 所有隐藏功能仍可通过菜单或快捷键访问；不能只用 title 提示承载关键操作。

## 4. 核心工作区原型

### 4.1 历史工作区

```text
历史 | 变更(3)       提交历史 / main                         详情 | 差异(4)
┌──────────────┬──────────────────────────────────────┬───────────────────┤
│ 全部提交      │ ●─┐  [main][origin/main] 修复事件权限 │ abc1234  提交详情  │
│ 本地分支      │ │ ●    补充主分支开发规则             │ 作者 / 提交者       │
│  ● main      │ ●─┘    完善文档                       │ 时间 / 父提交       │
│    feature/x │ ●      初始化项目                     │ [main] [v0.1]      │
│ 远程分支      │                                      │                   │
│ 标签          │ 过滤：信息 / 作者 / SHA / ref          │ 完整提交信息        │
│ Stash        │                                      │ ┌───────────────┐ │
│ 子模块        │                                      │ │ …             │ │
│              │                                      │ └───────────────┘ │
│              │                                      │ 包含于 / 操作 …    │
└──────────────┴──────────────────────────────────────┴───────────────────┘
```

- 提交图列固定显示节点与连线；信息列依次为引用、主题、作者、日期、短 SHA。
- 单击选中并加载详情；Enter 打开差异；再次点击不重复请求。
- Ctrl+单击最多选择两个提交：第二个选中后检查器显示「对比所选提交」，也可右键设为对比基准。
- 首版不支持 Shift 框选提交或批量执行历史改写，降低误操作面。
- 引用徽标可按类型着色，但 HEAD、远程、标签同时有不同图标 / 文本，不只靠颜色区分。
- 过滤只作用于当前仓库，清空过滤不重置选中提交；刷新尽量保留仍存在的选中项和滚动位置。
- 空仓库显示「暂无提交」及「打开变更工作区」；过滤无结果显示当前条件和「清除过滤」，不显示成仓库为空。

### 4.2 变更工作区

```text
历史 | 变更(6)       工作区变更                         [全部暂存] [刷新]
┌──────────────┬──────────────────────────────┬──────────────────────────┤
│ 工作区        │ 未暂存 (4)              [−] │ src/App.tsx        统一 diff │
│  未暂存 4     │ ☑ M  src/App.tsx            │ @@ -120,6 +120,8 @@       │
│  已暂存 2     │ ☐ A  src/ui/Panel.tsx       │ - old line                │
│  冲突 0       │ ☐ ?? docs/new.md            │ + new line                │
│ Stash        │──────────────────────────────│                          │
│ 子模块        │ 已暂存 (2)              [−] │                          │
│              │ M  src/types.ts              │                          │
│              │ A  src/ui/Menu.tsx           │                          │
│              │──────────────────────────────│                          │
│              │ 提交标题 ____________________ │                          │
│              │ 提交正文 [__________________] │                          │
│              │              [提交 (2) ▾]    │                          │
└──────────────┴──────────────────────────────┴──────────────────────────┘
```

- 中间为文件与提交编辑区，右侧为统一 diff；文件列表 / diff 宽度可调。
- 文件行单击预览，复选框只控制批量选择；双击文件表示暂存 / 取消暂存，并在按钮 title 与右键中提供相同操作。
- 未暂存与已暂存区均提供全选、暂存 / 取消暂存选中、暂存全部 / 取消全部；按钮文字随选择数量变化。
- 提交标题与正文分开，标题 50 字符、正文行 72 字符只作柔和提示，不阻止提交。
- 切换仓库保留提交草稿；关闭含未保存草稿的仓库页签需确认。成功提交后才清空草稿。
- 工作区轮询不覆盖正在编辑的草稿、文件勾选和手动合并内容。
- diff 工具条提供上一个 / 下一个文件、自动换行、文件列表 / 树切换和复制 patch；首版仍为统一 diff。

### 4.3 提交 / 分支对比

对比是历史工作区中的临时任务视图，可从两个提交、分支右键或命令栏进入。

```text
← 返回历史     比较 [main ▾] 与 [feature/ui ▾]   [交换] [复制范围]
┌───────────────────────┬──────────────────────────────────────────────┤
│ 文件 (12)  +248 −91   │ src/App.tsx                                  │
│ [列表 | 树] [过滤…]   │ @@ …                                         │
│ M  src/App.tsx        │ - …                                          │
│ M  src/styles.css     │ + …                                          │
│ A  src/ui/Panel.tsx   │                                              │
└───────────────────────┴──────────────────────────────────────────────┘
```

- 标题明确「A 与 B 的文件差异」，默认比较两端提交树，不把 `A..B` 日志范围与 tree diff 混为一谈。
- 交换只改变比较方向并重新计算增删，不丢失文件过滤和面板尺寸。
- 选择器接受本地 / 远程分支、标签和提交；无效或已消失的 ref 给出内联错误。
- 复用同一 diff 查看器、文件右键和键盘导航；返回历史恢复原选中提交与滚动位置。
- 「复制范围」复制两个完整 SHA，不复制可能随时间移动的短分支名。

## 5. 新 Git 工作流

### 5.1 冲突解决中心

冲突是变更工作区的任务模式。Pull、Cherry-pick、Revert、Rebase 或交互式 Rebase 产生冲突后，不再只弹错误，而是显示操作横幅和可恢复步骤。

```text
┌ Rebase feature/ui → main · 第 2/5 个提交 · 还有 2 个文件未解决 ───────┐
│ [继续 Rebase] [中止…] [查看 Git 输出]                    [刷新状态] │
├──────────────────┬───────────────────────────────────────────────────┤
│ 冲突文件 (2/4)    │ 当前：main（ours） │ 传入：feature/ui（theirs）   │
│ ⚠ src/App.tsx    │ ┌──────────────────┬────────────────────────────┐ │
│ ✓ src/types.ts   │ │ 只读版本          │ 只读版本                    │ │
│                  │ └──────────────────┴────────────────────────────┘ │
│ [上一个冲突]      │ 合并结果（可编辑）                    [保存 Ctrl+S] │
│ [下一个冲突]      │ ┌───────────────────────────────────────────────┐ │
│                  │ │ …                                             │ │
│                  │ └───────────────────────────────────────────────┘ │
│                  │ [采用当前] [采用传入] [上一个冲突块] [下一个冲突块] │
│                  │                         [保存并标记为已解决]        │
└──────────────────┴───────────────────────────────────────────────────┘
```

**状态与行为**

1. 顶栏使用实际操作两端名称，不只写 ours / theirs；Rebase 中 ours 的含义容易反直觉，必须同时显示 ref。
2. 当前版本与传入版本只读，合并结果可编辑。采用任一侧只替换结果编辑区，保存前仍可修改。
3. 切换有未保存修改的文件时提示「保存 / 放弃编辑 / 取消」；切换仓库不会丢失草稿。
4. 「保存并标记为已解决」是显式两步合一操作：保存工作区文件、stage 该文件、重新读取状态；任何一步失败都不显示成功。
5. 仍有冲突标记或未解决文件时禁止继续，并给出具体原因。继续按钮始终显示实际操作名，如「继续 Cherry-pick」。
6. 中止是危险操作，弹窗说明将丢失本次冲突解决进度；关闭窗口或切换仓库绝不自动中止。
7. 外部命令行也在操作同一仓库时，以重新读取的 Git 状态为准；发现状态变化后提示刷新，不覆盖编辑中的内容。
8. Git 原始输出可展开、复制；主界面先给可执行解释，再保留技术细节。

### 5.2 交互式 Rebase

从历史右键「从此提交的父提交开始交互式 Rebase…」或选择分支范围进入。编辑计划与执行计划分离，拖动列表本身不会改仓库。

```text
← 返回历史     交互式 Rebase：main → feature/ui       草稿 · 5 个提交
┌──────────────────────────────────────────────────────────────────────┐
│ 目标基底：main (a1b2c3d)     [全选 pick] [校验计划] [开始 Rebase…]   │
├──────────────────────────────────────────────────────────────────────┤
│ ☰  [pick ▾]   9f8e7d6  最新提交                       [Alt+↑] [Alt+↓] │
│ ☰  [squash▾]  8f7e6d5  补充测试                                        │
│ ☰  [reword▾]  7e6d5c4  更新界面                                        │
│ ☰  [drop  ▾]  6d5c4b3  临时调试                                        │
│ ☰  [pick ▾]   5c4b3a2  最旧提交                                        │
├──────────────────────────────────────────────────────────────────────┤
│ 预览：5 个提交 · 1 个 squash · 1 个 reword · 将丢弃 1 个提交          │
│ ⚠ 该操作会重写 feature/ui 的后续提交 SHA                               │
└──────────────────────────────────────────────────────────────────────┘
```

- 列表按**最旧在上、最新在下**排列，与 Git todo 语义一致；拖动和 Alt+↑/↓ 调整顺序，动作可用键盘选择。
- 首版动作：pick、reword、squash、fixup、drop；`edit` 可作为后续增强，不与首轮一起隐式扩张。
- 开始前的静态校验包括：工作区干净、范围有效、不是正在执行其它操作、第一个提交不能 squash / fixup、范围不含 merge commit。
- 工作区不干净时提示先提交或 Stash，**不自动 Stash**；存在其它 rebase / merge 状态时进入对应恢复视图。
- 开始弹窗列出基底、提交数、drop 数和将重写的分支；drop 非空时使用危险样式并要求再次勾选确认。
- 执行状态：`草稿 → 校验 → 执行 → 冲突 / 等待提交信息 → 完成或失败`。冲突进入统一冲突中心，继续后回到 Rebase 状态。
- reword / squash 的提交信息在任务内编辑，不打开外部编辑器；继续时以非交互方式调用 Git。
- 计划草稿只保存在当前前端仓库会话；应用退出不自动开始或继续任何历史改写。
- 中止需要确认；完成后保留结果摘要和「查看历史」，不永久保留已成功计划。

### 5.3 工作区文件操作

- **打开文件**：使用系统默认应用；**在文件管理器中显示**：定位到文件；**复制路径**：默认复制仓库相对路径，子菜单可复制绝对路径。
- **丢弃未暂存变更**：只作用于明确选择的已跟踪文件，弹窗列出路径；多文件显示数量和可展开清单。
- 未跟踪文件不混入普通批量丢弃；单独的「删除未跟踪文件…」需要再次明确确认，因为不可通过 Git 恢复。
- 已暂存内容不能通过「丢弃未暂存变更」一并删除；需要分别说明 index 与 worktree 的影响。
- 操作进行中锁定该文件行的重复动作，但不冻结整个应用；成功后精确刷新状态和相关 diff。
- 删除、丢弃、强制删除分支、中止 Rebase 等统一使用应用内危险确认弹窗，不再混用 `window.confirm`。

## 6. 命令、右键与键盘交互

### 6.1 命令组织

命令栏按三组排列，顺序稳定：

1. **视图**：导航显隐、刷新、当前分支切换。
2. **仓库动作**：Fetch / Pull / Push；工作区动作放在工作区工具条，不挤进全局栏。
3. **查找与系统**：过滤、通知、设置；空间不足时收入「更多」，不换成两行工具栏。

所有动作使用统一命令定义：`id`、标题、图标、快捷键、可见条件、启用条件、执行函数和危险级别。工具栏、右键、命令帮助引用同一命令，避免同一动作出现不同行为。

### 6.2 右键菜单矩阵

| 上下文 | 一级操作 | 分组 / 危险操作 |
|---|---|---|
| 仓库页签 | 打开仓库、关闭、关闭其它、复制路径、在文件管理器中显示 | 忙碌页签禁止关闭并说明；含草稿关闭需确认 |
| 本地分支 | 切换、基于此新建分支、与当前分支对比、复制名称 | 删除分支；强制删除需单独勾选 |
| 远程分支 | 与当前分支对比、复制名称 | Fetch 等远程动作独立分组 |
| 标签 | 与当前分支对比、复制名称 | 删除标签 |
| 提交 | 查看差异、复制 SHA / 主题、设为对比基准、新建分支 / 标签 | Cherry-pick、Revert、Rebase 到此处、交互式 Rebase 分组并二次确认 |
| 变更文件 | 暂存 / 取消暂存、打开、文件历史、Blame、复制路径 | 丢弃未暂存变更 / 删除未跟踪文件 |
| diff 文件 | 打开、文件历史、Blame、复制路径、复制 patch | 不写操作的上下文中不显示丢弃 |
| Stash | 应用、弹出、复制名称 | 删除 Stash |

**统一菜单行为**

- 右键先选中目标，再打开菜单；已有合法多选不被破坏。
- 菜单在视口边缘自动翻转，不超出屏幕；滚动、窗口失焦、Esc 或执行动作后关闭。
- 支持 ↑/↓、Home/End、Enter、左右方向键处理子菜单，以及 Shift+F10 / 菜单键打开。
- 禁用项保留并解释原因；危险项集中在底部，红色只用于危险项，不与普通 hover 混用。
- 菜单使用语义化按钮与焦点管理，不再以无键盘语义的 `div` 充当菜单项。

## 8. 反馈、加载与异常

### 8.1 三级反馈模型

| 层级 | 适用 | 表现 |
|---|---|---|
| 操作就地反馈 | 点击按钮、stage、保存、选择文件 | 按钮 spinner / 禁用、行状态、字段错误；防止重复提交 |
| 状态栏 | 当前仓库持续状态与最后一条结果 | HEAD、ahead/behind、已加载数量、当前操作、最后消息 |
| 通知中心 | 完成、失败、后台任务与 Git 输出 | 成功短 toast；错误持久保留，支持展开详情和复制 |

- 成功通知约 4 秒后消失，同时保留一条状态栏结果；连续 stage 等高频操作合并通知，不形成 toast 队列风暴。
- 失败通知不自动消失，关闭只清通知，不回滚仓库状态；提供「重试」（仅安全读操作）或「查看处理方式」。
- 长操作显示确定属于哪个仓库；没有真实进度时显示不确定进度和耗时，不伪造百分比。
- 切换仓库后，后台操作结果进入原仓库页签和通知中心，不把成功 / 错误显示成当前仓库结果。

### 8.2 状态覆盖

每个工作区都要设计以下状态，不能只设计正常路径：

- **首次加载**：面板骨架或局部 spinner，保留工具栏和布局，不让整个窗口变成一张 Loading 页。
- **后台刷新**：保留旧数据，行和按钮可用；写操作期间只锁定有冲突风险的动作。
- **空状态**：区分空仓库、无变更、无 diff、过滤无结果、无二进制预览，并给下一步动作。
- **部分失败**：日志成功而 ahead/behind 失败时，只在对应区域提示，不清空整个仓库。
- **过大内容**：patch 截断、blame 超限等保留明确说明；大内容加载不阻塞其它面板。
- **仓库不可用**：路径被删除或不再是仓库时，页签标错并提供「重新定位 / 关闭」，不自动删除最近记录。
- **离线 / 远程失败**：显示远程操作名和 Git 详情，不改变本地数据状态的呈现。

## 9. 多仓库与会话隔离

### 9.1 页签行为

- 打开已存在的仓库只激活原页签；仓库身份使用 discover 后的规范根路径，不用显示名称判断。
- 启动只恢复上次活动仓库；其它仓库从最近列表打开，避免一次启动并发加载多个大日志。
- 页签显示未提交点、冲突数或操作 spinner；这些状态是摘要，点击进入后才加载完整数据。
- 后台仓库暂停轮询；切回时先刷新状态，HEAD 变化再刷新日志。正在执行的 Git 写操作不因切页签取消。
- 关闭页签只关闭 UI 会话，不删除仓库；忙碌、含提交草稿或含未保存冲突编辑时按规则确认。

### 9.2 状态所有权

```text
AppShell
├─ 全局设置、主题、最近仓库、活动仓库 ID、通知中心
├─ RepositoryTabs
└─ RepoSession（每个打开的仓库一份）
   ├─ RepoInfo / 分支 / 标签 / 状态 / ahead-behind
   ├─ 日志 requestId、选中提交、滚动位置、过滤
   ├─ 当前工作区、检查器位置与尺寸
   ├─ 提交草稿、对比任务、Rebase 草稿、冲突编辑草稿
   └─ 当前写操作与错误
```

- 日志事件按仓库会话与 requestId 双重路由；关闭或刷新后，旧事件即使晚到也不能写入新会话。
- 选中详情、diff、ref 过滤和面板布局均在 RepoSession 内，禁止以单个全局 `repo` 覆盖所有页签。
- 后端仍无全局仓库状态，每次调用显式传规范仓库路径；前端多会话不能改变这一约束。
- 自动刷新不得清空用户输入；写操作后的刷新也要保留仍有效的选择和布局。

## 10. 前端模块划分

```text
AppShell
├─ RepositoryTabs / CommandBar / StatusBar / NotificationCenter
├─ Sidebar（引用导航与工作区切换）
├─ WorkspaceHost
│  ├─ HistoryWorkspace
│  │  ├─ RevisionGrid / CommitInspector / CompareTask / RebaseTask
│  └─ ChangesWorkspace
│     ├─ ChangeLists / CommitEditor / ConflictTask
├─ InspectorHost（右侧或底部，承载详情与统一 DiffView）
└─ OverlayHost（Dialog / ContextMenu / Toast / Tooltip）

shared/ui
├─ SplitPane / Panel / Tabs / Tree / VirtualList
├─ Button / IconButton / Input / Badge / EmptyState / Progress
└─ Menu / Dialog / Toast / FocusTrap

shared/commands
└─ 类型化命令定义、快捷键映射、菜单分组、启用条件
```

**边界规则**

1. `App.tsx` 只组合 Shell 和活动会话，不继续承载所有功能字段与弹窗分支。
2. 功能目录按 history / changes / compare / conflicts / rebase 划分，各自拥有视图、状态和 API 封装；共享逻辑才上移。
3. `DiffView` 保持统一展示组件，文件来源和写操作由调用方注入，不在 diff 内猜当前仓库。
4. `ContextMenu` 只负责定位、焦点和键盘，菜单项来自命令上下文；业务组件不各自实现一套浮层。
5. 命令注册是静态、类型化的应用内注册表，不做动态第三方插件系统。
6. 现有虚拟化、Worker 高亮、请求竞态处理和大小限制不能被布局重构绕过。

以下阶段都属于本轮已确认范围，按可独立验收的切片交付，而不是一次性改写全部界面。

| 阶段 | 交付内容 | 阶段完成判据 |

| E. 冲突中心 | 操作状态识别、冲突编辑、保存并解决、继续 / 中止、Git 输出 | merge / rebase / cherry-pick 冲突可恢复，未解决不能继续 |

每个阶段结束后先跑自动化与真实 GUI 验证，再进入下一阶段；复杂 Git 状态不与 Shell 重构在同一提交内完成。

## 13. 已确认决策

以下方向已确认并作为本轮实施边界：

1. 默认三栏、详情可右 / 底切换，首版不做任意拖拽停靠。
2. 对比和交互式 Rebase 是历史中的临时任务视图，冲突是变更中的任务模式。
3. 交互式 Rebase 首版限定线性范围，不包含 merge commit。
4. 视觉密度和配色按第 7 节执行；浅色主题仅预留设计令牌，不在首轮交付。
