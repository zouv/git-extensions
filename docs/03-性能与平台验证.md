# 03 · 性能测量与平台验证

> 记录可重复的验证方法及最近一次本机结果。测量方法变化时同步更新；不要把后端耗时当作完整 GUI 帧率。

## 大仓库性能测量

在 `src-tauri/` 下运行（仓库只读，不修改工作区）：

```sh
cargo run --release --example bench -- <仓库路径> 3
```

工具直接调用应用正式的 git2 日志、提交详情和 diff 实现，输出 JSON。指标：

- `firstBatchMs`：开始 revwalk 到首批非空日志（最多 300 条）产生的时间。
- `fullLogMs`：遍历全部提交并计算分支图布局的时间。
- `detailAvgMs` / `diffAvgMs`：最近 30 个提交的平均后端查询时间。
- `selectionP95Ms`：同一提交依次查询详情和 diff 的 P95；不含 IPC、React 渲染与 contained-in。

### 2026-10-31 Windows 实测

环境：Windows 10，release 优化构建，Git Extensions 源码仓库，17,783 条提交；同一进程连续三轮。

| 轮次 | 首批 300 条 | 完整 17,783 条 | 详情平均 | diff 平均 | 详情+diff P95 |
|---|---:|---:|---:|---:|---:|
| 1 | 115.77 ms | 169.02 ms | 3.81 ms | 17.98 ms | 32.56 ms |
| 2 | 103.77 ms | 152.22 ms | 3.41 ms | 17.21 ms | 28.04 ms |
| 3 | 113.24 ms | 165.10 ms | 3.91 ms | 18.89 ms | 30.13 ms |

这些结果证明后端核心查询在该仓库上为毫秒级，不等同于界面首屏、滚动帧率或完整提交切换耗时。与 Git Extensions 的 GUI 对比应在统一验收时于同一仓库、同一机器测量，未实测前不填写提升百分比。

## 跨平台验证

- Windows：运行 `test.bat`，覆盖前端生产构建、Rust 单测及真实仓库集成测试。
- Linux / macOS：安装 Tauri 前置依赖后运行 `sh test.sh`。
- `.github/workflows/build-and-test.yml` 提供 Windows、Ubuntu、macOS 三平台构建与测试矩阵；只有 CI 实际运行通过后才可将对应平台标为验证通过。

### 2026-10-31 验证结果

| 平台 | 前端构建 | Rust 测试 | 说明 |
|---|---|---|---|
| Windows 10 | ✅ | ✅ 13/13 | 本机实际执行 |
| Ubuntu 24.04（WSL2 x86_64） | ✅ | ✅ 13/13 | Node 22、Rust stable，独立 Linux 副本实际执行 |
| macOS | 待统一验收 | 待统一验收 | ICNS/PNG 图标及 CI 矩阵已配置，当前无 macOS 执行环境，未声称通过 |

Linux 首轮构建发现默认 PNG 图标缺失，已生成完整 Tauri 多平台图标并在 `tauri.conf.json` 配置打包资源，随后 Windows / Linux 测试均通过。GUI 显示、输入法、快捷键冲突与安装包仍属于各平台人工验收范围。
